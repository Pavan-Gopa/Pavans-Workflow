# Visual hierarchy

- One dominant current task, action, or state per surface.
- Separate live state from user selection; never force the user to infer which
  item is actually running.
- Use spacing, alignment, weight, and contrast before adding containers.
- Keep secondary metadata readable but visually subordinate.
- Preserve density appropriate to the product. Utility and professional tools
  should not become marketing pages.
- Reuse existing typography and token scales. Introduce a new token only when a
  repeated semantic role is genuinely missing.
- Destructive, blocked, warning, and success states must remain distinct without
  relying on color alone.
